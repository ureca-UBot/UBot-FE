# UBot Frontend

**질문부터 상품 이용, 매장 방문, 상담사 연결까지 이어지는 통신 고객 서비스 화면입니다.**

고객은 AI 채팅에서 공식 안내와 조회 자료를 확인하고, 상품·MY·매장·고객센터 화면에서 필요한 업무를 처리합니다. 상담사는 고객의 이전 대화를 이어받고, 관리자는 FAQ와 미응답, 상품·매장·문의, 안전 정책과 운영 상태를 관리합니다.

[서비스 이용하기](https://u-bot.cloud) · [전체 기능 문서](docs/README.md) · [UBot 전체 소개](https://github.com/ureca-UBot) · [Backend](https://github.com/ureca-UBot/UBot-BE)

## 고객이 이용하는 흐름

1. **질문하고 근거를 확인합니다.** 첫 화면은 AI 채팅입니다. 답변이 준비되는 단계를 확인하고, 상품·가입 정보·매장 카드를 함께 봅니다. 다른 의도로 다시 검색하거나 답변에 의견을 남길 수 있습니다.
2. **필요한 업무로 이동합니다.** 상품 상세에서 가입을 신청하고 MY에서 회선·이용 정보를 조회합니다. 매장을 찾으면 경로와 방문 가능 시간을 확인해 예약합니다.
3. **사람의 도움이 필요하면 상담사를 호출합니다.** 현재 대화의 저장된 AI 문답·FAQ·이전 상담 기록을 자동으로 인계합니다. 종료 후 추가한 문답도 재상담에 포함합니다.
4. **기록과 처리 결과를 다시 확인합니다.** 최근 대화, 문의 답변, 예약 내역, 이용 알림을 각 화면에서 조회합니다.

상담사는 인계받은 대화와 FAQ를 읽고 상담을 이어 갑니다. 관리자는 답하지 못한 질문을 모아 FAQ를 보완하고 재검증합니다. 고객의 질문이 상담과 지식 개선으로 이어지는 흐름을 같은 서비스에서 제공합니다.

|---|---|---|

| 상담사 연결 | 회원 상담 요청, 자동 이력 인계, 대기 중 다른 대화 이용, 상담사 배정·메시지 검사 상태, 종료·재상담 | [상담사 연결](docs/COUNSEL_WORK_SUMMARY.md) |
| FAQ·미응답 개선 | FAQ·카테고리·유사 질문·복구, 이용·검색 품질 분석, 개선 후보 검토·제외, 미응답 그룹과 FAQ 전환·재검증 | [지식 관리](docs/features/knowledge-management.md) |

관리자는 상품·매장·예약·공지·문의도 각 관리 화면에서 처리합니다. 기능별 문서에는 고객 화면에서 시작한 요청이 관리자 화면으로 이어지는 과정과 API 연결을 함께 적었습니다.

## 계정별 시작 위치

| 계정 | 시작 화면과 이동 |
|---|---|
| 비회원·일반 회원 | `/#/` 또는 `/#/ai`. 로그인하면 저장 대화와 본인 정보, 예약·문의·상담을 이용합니다. |
| 상담사 | 로그인하면 `/#/counselor`로 이동합니다. 홈 헤더의 **상담사 화면** 버튼으로도 들어갑니다. 데스크톱과 모바일에서 상담사 계정에만 표시합니다. |
| 관리자 | 로그인하면 `/#/admin/dashboard`로 이동합니다. 홈 헤더의 **관리자 화면**으로 돌아갈 수 있습니다. |

화면의 역할 검사와 별도로 BE가 각 요청의 권한과 소유권을 검사합니다. [인증과 데이터 흐름](docs/features/chat-and-history.md#회원과-대화-기록)을 참고하세요.

## 한 대화를 끝까지 확인하기

BE에 검색 가능한 FAQ와 사용자·상담사 계정이 준비되어 있다면 다음 순서로 확인할 수 있습니다. 서로 다른 브라우저 프로필로 두 계정을 엽니다.

| 순서 | 실행 | 확인할 결과 |
|---|---|---|
| 1 | 사용자 홈에서 등록된 FAQ의 질문 전송 | 질문 접수 후 진행 상태가 바뀌고 답변 표시 |
| 2 | 추천 FAQ 선택 후 **상담사 호출** | 같은 대화에서 상담 대기. 저장된 AI 문답·FAQ 자동 인계 |
| 3 | 상담사 홈의 **상담사 화면**에서 상담 가능으로 전환 | 배정 후 이전 문답을 확인하고 고객과 메시지 교환 |
| 4 | 상담 종료 → AI 질문·FAQ 선택 → 새로고침·재로그인 → 최근 대화에서 재상담 | 상담사가 추가 문답과 이전 상담의 허용된 메시지 확인 |

[자동 인계 브라우저 테스트](scripts/counsel-handoff.test.cjs)는 이 흐름의 요청 값과 화면 복원을 고정 응답으로 검사합니다. 실제 서버에서 확인할 조건은 [개발과 검증](docs/development.md#브라우저-회귀-테스트)에 정리했습니다.

## 로컬에서 실행하기

CI와 같은 Node.js 22 환경을 권장합니다. Vite의 최소 지원 버전은 Node.js 20.19 또는 22.12입니다.

```bash
git clone --branch develop https://github.com/ureca-UBot/UBot-FE.git
cd UBot-FE
npm ci
npm run dev
```

개발 서버가 출력한 주소를 엽니다. 기본 주소는 `http://localhost:5173/#/ai`입니다. 실제 API는 기본적으로 `http://localhost:8080`의 BE로 전달합니다. 지도 키·다른 서버 주소·개발용 응답 설정은 [개발과 검증](docs/development.md)에서 설명합니다.

```bash
npm run lint
npm run format:check
npm test
npm run build
```

검사를 통과하면 `dist/`에 정적 파일을 만듭니다. 기본 빌드는 GitHub Pages 경로를 사용하고, AWS의 루트 경로용 빌드는 `npm run build -- --base /`를 사용합니다. [AWS 배포와 복구](docs/AWS_DEPLOY.md)에서 실제 배포 경로를 확인할 수 있습니다.

## 화면과 서버의 역할

React 19·TypeScript·Vite 8로 구현했습니다. 화면은 `/api`로 BE에 요청하고 처리 상태를 조회합니다. 임베딩·검색·모델 호출과 최종 업무 판단은 BE가 담당합니다. FE가 모델이나 데이터베이스에 직접 연결하지 않습니다.

**사용자·상담사·관리자 화면 → 공용 인증·API 클라이언트 → UBot-BE → 검색·모델·업무 데이터** 순서로 연결합니다. 지도 화면은 Kakao SDK를 사용하며, 매장·길찾기 자료는 BE에서 받습니다.

채팅 상태를 라우트 밖에 두어 화면을 이동해도 질문을 이어 가고, 접수와 완료를 나눠 대기·재시도·중단을 표시합니다. 상담은 화면의 문답을 복사하지 않고 대화 ID로 서버 저장 이력을 이어받습니다. 선택 이유와 제약은 [내부 동작과 연동 계약](docs/internals.md)에 정리했습니다.

## 검증 범위와 표시값

| 확인하려는 내용 | 검증 근거 |
|---|---|
| 요청·응답 처리, 상태 전이, 계산 | `npm test`와 [실행 명령](docs/development.md) |
| 사용자·관리자·상담사 화면, 오류 대응, 모바일 배치 | [브라우저 테스트 목록](docs/development.md#브라우저-회귀-테스트). API 응답을 고정한 검사 |
| 리팩토링 전후 화면·번들 비교 | [당시 측정 결과](docs/FE_REFACTOR.md). 현재 빌드의 새 측정값으로 해석하지 않음 |
| 실제 로그인·검색·답변·상담 저장 | 실행 중인 BE와 실제 계정으로 별도 확인 |

상품 가입 화면은 서버의 가입 기록 API와 연결합니다. 실제 통신사 개통·결제 기능을 뜻하지 않습니다. MY의 예정 청구액은 화면에서 계산한 추정치이며, 데이터 잔량 일부는 제공량 기준 표시입니다. AI 사용량 카드와 저장 청구 내역 조회는 별도 API 응답을 사용합니다. [표시값의 범위](docs/features/products-and-my.md#금액과-사용량을-읽는-기준)를 참고하세요.
