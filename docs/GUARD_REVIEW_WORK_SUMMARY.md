# 관리자 AI 금칙어·위험 문장 검토

- 화면: `/#/admin/forbidden-words/review` (금지어 관리에서 진입)
- 분석 설정: `?view=settings`, 후보: `?view=candidates`, 경고: `?view=warnings`, 이력: `?view=history`
- 주기 설정·후보 수정·오차단 재검사·검사한 버전 승인·위험 문장 경고·알림 확인을 제공합니다.
- 기존 관리자 인증·API 클라이언트·금지어 목록·페이지네이션·모달 포커스를 재사용합니다.
- 위험 문장 경고를 확인해도 금칙어로 자동 등록하지 않습니다.
- 수정된 후보·만료된 검사·정상 오차단·기존 차단 누락은 승인을 막습니다. 최종 승인은 서버가 다시 검증합니다.

## 백엔드 준비

실제 동작에는 UBot-BE PR #264의 `/api/admin/guard-review` API와 V42 마이그레이션 배포가 필요합니다.
API가 아직 없으면 준비되지 않았다는 안내를 표시하며 기존 금지어 관리로 돌아갈 수 있습니다.
프론트에서 DB나 LLM을 직접 호출하지 않습니다. 샘플 서버·샘플 화면 도구는 운영 번들에 포함하지 않습니다.

## 검증

`npm test`, `npm run lint`, `npm run format:check`, `npm run build`를 실행합니다.
관리자 화면 브라우저 검증은 `node --test scripts/guard-review-browser.test.cjs`이며, API 응답을 모의 처리합니다.
실제 배포된 API·관리자 인증·LLM 분석 품질 검증을 대신하지 않습니다.

## 가드 검사 기록: 다중 조회와 선택 항목 분석

- `GET /api/admin/guard-review/checks`는 `origins`·`outcomes`를 반복 파라미터로 받습니다. 같은 조건 안에서는 OR, 출처와 결과 사이는 AND입니다. 기존 단일 `origin`·`outcome`도 계속 지원합니다.
- 검사 생략 요약은 `skippedOrigins`에 포함된 출처로 검색해도 한 행으로만 표시합니다.
- 기록을 선택하고 `선택 항목 AI 분석`을 누르면 `POST /api/admin/guard-review/checks/analysis`에 `checkIds`를 보냅니다. 선택은 페이지를 넘겨도 유지되고 필터를 바꾸면 해제됩니다.
- 분석할 수 있는 기록은 원문이 보관 중이고 질문이 있으며 `INPUT_*`·`OUTPUT_*` 출처의 통과·정리·차단·보류·오류 판정입니다. 검사 생략 요약과 원문 만료 기록은 선택할 수 없습니다. 서버도 같은 조건으로 검증하며, 조건에 맞지 않는 기록이 섞이면 요청 전체가 거절됩니다.
- 선택 건수에는 서버 상한이 없습니다. 100건을 넘게 선택하면 확인 후에만 접수합니다. 분석은 한 번에 하나만 실행됩니다.
- LLM 판정 보류 기록은 같은 작업에서 재검토하고 결과를 상세 화면의 `관리자 AI 판정`으로 보여 줍니다. 원래 가드 판정과 사용자 답변은 바뀌지 않습니다.
- 서버가 `capabilities.checkMultiSelect`·`checkSelectionAnalysis`를 알려 주지 않으면(구버전) 다중 선택과 선택 분석을 비활성화하고 기존 조회만 제공합니다.

## 실행 요약 객체·검사 사례 페이지 API 후속 연동

- 개요/실행 상세의 `ReviewRun.result`를 문자열에서 객체로 변경했습니다. `JSON.parse`와 전체 `cases` 배열 의존을 제거하고 버전·건수·오차단/회귀 집계가 유효한 요약만 읽습니다.
- 승인 버튼은 완료·미만료 VALIDATION 실행의 `caseCount > 0`, 전체 오차단/회귀 집계, 검사한 후보 묶음·현재 후보 버전과 상태를 확인합니다. 현재 페이지의 사례 수나 조회 성공 여부를 전체 검사 통과 여부로 사용하지 않습니다. 최종 승인은 기존 백엔드가 다시 검사합니다.
- `GET /api/admin/guard-review/runs/{id}/cases?page=0&size=20`으로 요청한 사례 페이지만 읽습니다. 기존 금칙어 페이지 크기(10/20/50)·페이지 이동 컴포넌트와 공통 API 클라이언트를 재사용합니다. 페이지 크기를 바꾸면 첫 페이지로 이동하고 전체 페이지를 미리 읽지 않습니다.
- 이전에는 브라우저에 전체 배열을 받은 뒤 변경 사례를 필터링했습니다. 새 API는 전체 사례를 순서대로 페이지화하므로 화면에도 정상 유지/기존 기준 미충족을 포함한 현재 페이지 전체 사례를 표시합니다. 전체 집계와 현재 페이지 범위를 구분하며, 한 페이지만 읽고 전체 변경 사례를 확인했다고 표시하지 않습니다.
- 새 검사·후보 수정·후보 페이지 변경 시 이전 사례 화면을 폐기합니다. 요청 취소와 요청별 응답 구분으로 페이지 전환·언마운트 후 늦게 도착한 응답을 표시하지 않습니다.
- 일시적인 사례 조회 실패는 현재 페이지 다시 불러오기를 제공합니다. 만료·삭제·조회 불가(404/409/410) 시 검사 요약도 폐기하고 재검사를 안내합니다. 주기 실행 상세 조회에서 확인한 만료 역시 캐시된 사례와 승인 상태를 제거합니다.
- 사례 원문은 기존처럼 React 텍스트/`pre`로만 표시합니다. 상담·가입 정보 카드·채팅 취소·좋아요/별로예요·상품 검색 유지·금칙어 직접 관리·공통 API/페이지 이동 구현은 수정하지 않습니다.
- 관련 로직·브라우저 테스트의 가짜 응답도 새 요약/페이지 계약으로 맞췄습니다. 5,168건 페이지 이동·10/20/50개 조회·일시 오류 재조회·만료 승인 차단·전체 집계에 따른 승인 판단·후보 수정 후 늦은 응답·HTML 텍스트 표시를 검증합니다. 실제 백엔드·DB·LLM은 호출하지 않습니다.
