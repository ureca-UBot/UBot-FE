## 상담 기능 분리

기존 `feat/200-counsel-ui` 작업 디렉터리를 그대로 보존하고 별도 worktree에서 시작했습니다.

상담 변경은 작업 공간의 `.archive/fe-counsel-20261020`에 패치·파일 사본·SHA-256 목록으로 보관했습니다.

## 변경 내용

| 영역 | 책임 분리와 유지 사항 |
| --- | --- |
| 라우팅 | `App`에서 사용자·관리자 진입점을 분리하고 `AdminApp`에 관리자 라우트를 모았습니다. 기존 HashRouter 경로와 별칭을 유지합니다. |
| 로딩 | 사용자·관리자·두 대시보드 번들을 나눴습니다. 관리자 차트 코드는 일반 사용자 진입에 포함되지 않습니다. |
| 사용자 화면 | `UserApp`의 화면 조립과 `useUserExperience`의 이벤트·데모 상태를 분리했습니다. 처음 방문한 페이지를 마운트하고 이후에는 입력·필터 상태를 유지합니다. |
| 채팅 | 상위 화면의 질문 전송 구독과 실제 채팅 상태 구독을 분리했습니다. 상태 전이와 응답 판별은 독립 함수로 추출했습니다. |
| 관리자 업무 | 상품·매장·공지·금지어·미답변·예약·문의의 상태와 요청을 도메인별 훅으로 옮겼습니다. 표·폼·API 경로는 유지합니다. |
| 대시보드 | 1,283줄 페이지를 21줄 화면 조립 코드와 섹션·차트·조회 목적별 훅으로 분리했습니다. |
| 공통 계약 | 상품·예약·문의 타입을 `shared`로 옮겨 관리자 코드의 사용자 도메인 의존을 제거했습니다. 기존 import 경로에는 필요한 호환 export를 유지합니다. |
| 지도 | 경로 항목 변환, 매장 목록·버블 DOM, 마커 이미지를 분리했습니다. 정리된 지도에 늦은 응답이 오버레이를 다시 만들지 않도록 요청을 무효화합니다. |
| CSS | 사용자 CSS를 22개 영역으로, 관리자 CSS를 3개 영역으로 나눴습니다. 원래 선언·순서·선택자를 그대로 보존했습니다. |
| 안정성 | FAQ 검색의 이전 응답을 취소·무시하고 조회 오류와 재시도를 처리합니다. 카테고리 조회 실패가 미처리 Promise 오류로 남지 않도록 했습니다. |
| 접근성 | 관리자 모달 18개에 포커스 진입·Tab 순환·Escape·호출 위치 복귀를 적용했습니다. 중첩 모달은 가장 위의 모달만 키 입력을 처리합니다. |
| 컨벤션 | 기존 도메인 구조를 유지하며 TypeScript/TSX 포맷을 통일했습니다. TypeScript의 기존 strict 동작을 설정에 명시했습니다. |

포맷 정리만 포함된 파일도 있습니다. 기능별 표·폼·페이지네이션을 하나의 범용 컴포넌트로 강제 통합하지 않았습니다.

## 검증 결과

- `npm run format:check`: 통과.
- `npm run lint`: 통과.
- `npm test`: 11개 통과. 경로, 채팅 상태 전이, 응답 검증, 상품 검증, 지도 좌표, 동시 토큰 재발급, 인증 실패 처리, 폴링 완료·취소, CSS 원문 보존을 검사합니다.
- `npm run build`: TypeScript 검사와 production 빌드 통과. 500 kB 초과 청크 경고가 제거됐습니다.
- 브라우저 화면 비교: 데스크톱·모바일 총 **49개**, 텍스트 49개 일치, 페이지 오류 0개. 48개는 픽셀 차이 0입니다.
- 남은 1개는 관리자 게스트 설정의 날짜 영역 89픽셀 차이입니다. 포맷터가 분할한 JSX 텍스트를 원래 형태로 복원했으며 최종 재비교가 필요합니다.

마지막 브라우저 비교 후 대시보드 훅과 차트 로딩 경계를 추가 정리했습니다.
추가 브라우저 기능 테스트 실행은 로컬 서버 접속을 위한 권한이 승인되지 않아 실행하지 못했습니다.
따라서 날짜 JSX 수정과 최종 코드에 대한 전체 브라우저 재검증 완료로 간주하지 않습니다.
카카오 SDK·실제 서버·실계정 연동은 이 고정 응답 테스트의 검증 범위에 포함되지 않습니다.

## 재실행

Node 22 이상에서:

```sh
npm ci
npm run format:check
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:browser
npm run test:visual
```

설치된 Edge를 사용하는 PowerShell 환경:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:browser
npm run test:visual
```

시각 비교는 기준 commit을 `test-results/develop-baseline`에 풀고 현재 `node_modules`를 연결합니다.
기준 commit을 포함하는 Git 이력이 필요합니다. 이미 준비한 별도 checkout은 `REFACTOR_BASELINE_DIR`로 지정할 수 있습니다.
기준 화면·변경 화면 PNG와 결과 JSON은 `test-results/refactor-visual`에 저장하며 Git에서 제외합니다.
`VISUAL_CASE`로 특정 파일명 부분 문자열에 해당하는 화면만 실행할 수 있습니다.
실제 인증정보 대신 테스트용 응답과 가짜 토큰을 사용합니다.

기존 CI에는 포맷·논리 테스트를 추가했습니다. 브라우저 전체 검증은 `Frontend Browser Regression` 수동 workflow에 연결했습니다.
